# 从业务仓读取项目事实

通用 skill 提供做法。当前业务 checkout 提供项目约束、产品行为、开发环境和交付约定。开始时从目标工作目录确认仓库根、分支、SHA 与 dirty 状态。保留已有修改，运行命令前核对工作目录。

## 两类路径

- 项目文件、工作区和测试产物以当前目标 checkout 为准。先读适用的仓库指令、README 和它们指向的文档，按问题沿索引找到当前行为、现有脚本与配置。用户指定了其他位置时按任务使用。
- skill 正文与附带资料以所加载的 `SKILL.md` 所在位置为准。若通过安装目录的链接加载，解析到实际源码目录再定位随附的 `references/` 或 `scripts/`。从项目工作目录调用附带 CLI 时使用脚本的绝对路径，给项目文件参数时也要核对其所属 checkout。

## 按任务查找

| 需要确定什么 | 从业务仓查找什么 |
| --- | --- |
| 开发与交付 | 默认基线与交付目标、变更记录位置、提交约定与适用的 CI |
| 实现与验证 | 当前契约、相关源码和测试、包管理器、构建命令、配置与运行前置 |
| 产品体验与试用 | 产品定位、设计系统与相邻界面、用户入口、适用平台、项目场景与测试身份 |
| 运行与性能 | 当前验收环境、隔离方式、网络复现入口、负载和观测点 |
| 模型行为 | 请求捕获方式、会话和轮次定位、代理日志及脱敏约定 |
| 取证与收尾 | 本地证据目录、结果记录和资源回收要求 |

使用已存在的代码与命令补足文档未覆盖的事实。文档与行为冲突时标明待核实处。没有项目专用导引的仓库可直接使用现有 README、测试和运行入口。远端、PR、固定分支、CI 和额外主机都依实际配置决定。只有本地仓库时，以当前 checkout 为基线，按既有约定验证和交付到本地。仅在缺失信息实际影响正确性、执行授权或必要验证时说明缺口。

## 隔离运行与资源回收

优先使用本项目验证脚本或调用者已经准备且版本可信的环境。根据受影响范围隔离端口、配置、测试身份、数据、外部资源和工作目录。无法完成必要观察时记录具体原因。需要验证网络延迟或断连时，优先使用能覆盖触发条件的项目认可环境，记录客户端、服务端与实际入口。单机验证足够时可在本机完成；用本地模拟近似跨机条件时写明证据边界。

结束时按项目约定停掉本轮服务并回收本轮创建的数据、身份、浏览器会话及临时文件，核实资源状态。归还借用的环境，保留证据或等待处理的资源要交代位置、负责人和回收条件。证据如何记录与保存见 [Evidence](evidence.md)。
