# Evidence

验证记录应能把具体声明、方法、运行结果、证据位置与适用边界连起来。用业务仓的实际入口执行并按其交付约定保存。一次交付通常需要多种证据。

| 类型 | 直接观察 | 仍需另查 |
| --- | --- | --- |
| unit、integration、contract 测试 | 指定代码行为及边界是否可重复通过 | 部署或真实进程装配、完整产品体验 |
| 客户端测试与构建 | 定义的客户端行为、构建结果 | 真实后端连接、实际布局和完整交互 |
| 真实产品 E2E、真栈走查 | 给定版本、角色、环境与入口下的用户结果 | 未操作的状态、其他平台和未来回归 |
| 设计、代码或专项审查 | 受审范围内的设计或实现判断 | 技术检查之外的真实交付证据 |
| 服务状态和日志 | 运行中的进程、连接、事件、报错 | 其他时间或环境的行为、长期契约 |
| 模型请求与响应 | 实发输入和响应链路 | 应用是否正确消费、结果是否送达 |
| 本地或远端 CI | 指定版本在该环境实际运行的检查结果 | 工作流之外的验证 |

最窄测试先反馈直接影响，再根据风险扩展到必要的装配、端到端路径或独立审查。复用当前版本下可信、仍有效的证据。核对实际运行的 CI 工作流、测试集合和提交 SHA，按需补足对应证据。

## 一条可复查记录

- **声明**说明具体行为或退出标准。
- **基线**记录 branch、commit SHA、影响结果的 dirty 状态、构建、环境和配置。
- **方法**给出可运行的命令，或入口、用户操作、身份和视口等复现条件。
- **结果**以 pass、fail 或 inconclusive 表明判定并给出关键观察。
- **定位**保存测试名、构建或 CI 记录、截图路径、日志 session、轮次或事件标识。
- **限制**说明本证据没有覆盖的状态、环境和行为。相关性与因果是否已证实各自说明。

## 保存和使用

将证据摘要和定位归入项目既有的实施、评审或验收记录。保留版本与执行者，避免在多处维护同一结论。为文件按场景和状态命名，并写明它们对应的声明和运行基线。

### 截图与录屏的交接

设计对照和视觉验收需要实际画面时，保存能说明问题的代表性原图。默认放在仓外或被 Git 忽略的产物目录。unit 或 PR 记录版本、场景、关键观察、复现步骤，以及适合读者使用的证据定位。

- 给另一位 Agent 复核时，同机且共享文件系统可交接绝对路径；跨机器或隔离环境使用接收方有权读取的附件或共享产物链接。让复核者能打开原图，保留到相关复核结束；worktree 会先回收时提前转存。
- 给用户确认效果时，在回复中直接展示代表图或前后对照，附一句标明场景、版本或样例数据。使用用户能打开、交付后仍可访问的附件或产物位置。
- 按项目约定长期维护的图片可以随代码提交，例如视觉回归测试实际读取的基准图、正式文档插图，或用户明确要求版本化的交付物。提交前核对用途并脱敏。

请求原件、日志、运行数据等按项目约定存放。敏感原件仅留在 gitignored 或仓外受控位置，报告使用必要的脱敏摘要。依赖临时会话的证据应在清理前妥善保存。已经回收的原件标明状态，避免把失效位置写成可复查证据。证据转为长期保护时，将各自归入测试或 CI、当前行为契约、架构说明、开发指引或运行手册。本次特有的判断与当时证据留在变更历史。
